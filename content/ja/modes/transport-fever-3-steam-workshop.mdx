## Transport FeverシリーズにおけるMod文化の進化

本フランチャイズは、古くからコミュニティの創造性を称賛し、後押ししてきました。開発のUrban Gamesは長年にわたり統合環境を着実に強化し、初期の手動ファイル展開からシームレスなワンクリックサブスクリプションへと進化させてきました。

コミュニティのクリエイターが単なるスキン変更から完全な動的モジュールアセットへとシフトしたことで、ゲームプレイの奥深さは爆発的に増大しました。初期の作品では、側線や拡張貨物ターミナルを追加するだけでも、完全に別の建物アセットを導入する必要がありました。しかし現代のツールセット環境では、動的スクリプト、リアルタイムなプロシージャル線路敷設、そしてリアルな架線配置が標準仕様として求められています。

Transport Fever 3のSteam Workshopを活用することは、モッダーたちが10年以上にわたって洗練させてきた車両物理、サウンドデザイン、カスタム信号ロジックの成熟したエコシステムに足を踏み入れることを意味します。

## Transport Fever 3 Steam Workshopで期待されるアセットカテゴリ

新しいシミュレーションが発売されると、Modコミュニティはその制作物を明確な機能別の柱に分類します。Transport Fever 3のSteam Workshopにおいても、これらのカテゴリによってプレイヤーは見た目のディテール、経済のバランス、物理インフラを個別にカスタマイズできるようになります。

```
Modエコシステムの構造:
├── 基幹インフラ（駅、線路形状、橋梁）
├── 車両＆フリート（機関車、道路車両、航空機、船舶）
├── スクリプト＆自動化（ダイヤ設定、運行管理、カスタムロジック）
└── ビジュアル＆環境（バイオーム、カスタムテクスチャ、景観アセット）
```

### 1. 車両および地域フリート
大陸ごとに独自の鉄道文化、信号規格、車両限界が存在します。バニラ版でもバランスの取れたヨーロッパ、アメリカ、アジアの基本パックが用意されていますが、モッダーたちは歴史の空白を素早く埋めていきます。期待できる要素は以下の通りです：

*   リアルな牽引力曲線と排気パーティクル効果を備えた、大戦前の蒸気機関車。
*   カスタム連節台車とリアルな加速プロファイルを再現した現代の高速列車（EMU）。
*   超長編成の鉱物バルク輸送向けに構成された重量級ディーゼル電気機関車。
*   超低床ライトレール、連節電気トロリーバス、2階建てバスなどの地域密着型都市交通車両群。

### 2. インフラおよび駅モジュール
現代の路線設計にはモジュール化が不可欠です。固定デザインの駅を選択するのではなく、モジュール式コンポーネントを組み合わせることで、山間部の峠道に沿ってホームをカーブさせたり、高層ビルが立ち並ぶ都心の直下に地下鉄ターミナルを組み込んだりすることが可能になります。

### 3. スクリプト、運行ロジック、経済チューニング
すべてのModが見た目を変えるものとは限りません。本格派の運行管理者たちは、見た目の多様性よりも運用の奥深さを重視します。スクリプトModはメンテナンスの減価償却曲線、都市の成長アルゴリズム、貨物の時間劣化などを調整し、極めてシビアな経済シナリオを生み出します。

| Workshop Modカテゴリ | 平均的なメモリ消費量 | プレイヤーへの主なメリット | セーブデータ破損リスク |
| :--- | :--- | :--- | :--- |
| **車両パック** | 高（1パックあたり500MB〜2GB） | 各時代の視覚的多様性を拡張 | 最小限（アセット消失時は代替モデルに置換） |
| **モジュール式駅アセット** | 中（100MB〜400MB） | プラットホーム長の自由変更、旅客導線の分離 | 中程度（駅の専有面積変更でルートが無効化される恐れあり） |
| **スクリプト交通＆AI Mod** | 低（< 50MB） | 車両間隔のリアル化、優先運行管理 | 高（エンジンのコアに作用するためパッチ後に不安定化しやすい） |
| **環境＆マップテクスチャ** | 高（1GB〜4GB） | フォトリアルな道床、植生、水面表現 | 低（地形シェーダーの見た目のみを変更） |
| **経済オーバーホール** | 極小（< 10MB） | シビアな収益管理、リアルな運賃設定 | 中程度（新規セーブ推奨または慎重な車両再配備が必要） |

## ロード順の整理とシステムパフォーマンスの最適化

多種多様なコミュニティアドオンを導入するとゲームの魅力は飛躍的に高まりますが、無秩序にインストールするとフレームレートが著しく低下します。Transport Fever 3のSteam Workshopを何時間も閲覧していると、ベテランプレイヤーが「アセット肥大化（Asset Bloat）」と呼ぶ状態に陥りがちです。

数百もの精密な鉄道モデル、高解像度4Kテクスチャ、カスタムサウンドスクリプトが同時に実行されると、システムリソースに大きな負荷がかかります。仮想メモリの割り当てを監視し、Modの有効化順序を整理することで、クラッシュやスタッター（カクつき）を未然に防ぐことができます。

```
推奨ロード順ヒエラルキー:
[1. ベースライブラリ＆フレームワーク] ➔ [2. 地形＆マップジェネレーター] ➔ [3. インフラ＆駅] ➔ [4. 車両＆フリート] ➔ [5. UI＆オーバーホールスクリプト]
```

### 重要な最適化戦略
1.  **テクスチャ容量の管理：** 高ポリゴンアセットは車庫でズームした際には息をのむほど美しく見えますが、中央ハブに何十台も密集するとGPUのVRAMを圧迫します。利用可能な場合は、圧縮テクスチャ版を選択してください。
2.  **アセットの依存関係を確認：** 複雑な建造物は、コミュニティ製のベースライブラリを必要とすることが多々あります。個々のモジュールパーツを読み込む前に、必ず前提となるユーティリティパックをサブスクライブしてください。
3.  **未使用Modの整理：** アセットをサブスクライブしたままにしておくとストレージを消費するだけでなく、進行中のセーブデータで有効化されたままの場合、ゲームエンジンがスクリプトや設定テーブルをメモリ上に保持し続けます。使っていない地域パックは無効化しておきましょう。

| 症状 / エラー | 根本原因 | 推奨される対処法 |
| :--- | :--- | :--- |
| **都市ズーム時のスタッター** | 街頭オブジェクトやバスのポリゴン過多 | LOD表示距離を下げる、または装飾用プロップパックを削除する |
| **ロード84%でのクラッシュ** | スクリプトの前提Mod不足、またはUI Modの競合 | stdout.txtのクラッシュログを確認し、ベースフレームワークが有効か確認する |
| **テクスチャのピンク化/欠落** | マテリアルパスの破損、または非互換の圧縮形式 | Workshopからアセットを再インストールし、シェーダーキャッシュをクリアする |
| **都市人口の暴走によるラグ** | Modによる都市成長乗数の過剰設定 | 都市成長スクリプトの設定値をデフォルト寄りに戻す |
| **信号で列車が立ち往生する** | カスタム信号ロジックによる経路探索の競合 | カスタム信号スクリプトを標準の閉塞/パス信号に置き換える |

## Workshopでのカスタムコンテンツの作成と公開方法

コミュニティの生命線は、魅力的なアセットをゼロから作り上げるクリエイターたちにあります。Transport Fever 3のSteam Workshopに3Dモデルや機能スクリプトを投稿したいと考えているなら、標準的な制作パイプラインを把握しておくことが不可欠です。

現代のアセット制作には、クリーンなトポロジー、物理ベースレンダリング（PBR）ワークフロー、そしてLuaで記述された綿密なメタデータスクリプトが求められます。

```
アセット開発フロー:
[資料収集] ➔ [3Dモデリング（Blender）] ➔ [PBRテクスチャ作成（Substance）] ➔ [Luaスクリプト作成] ➔ [ローカルテスト] ➔ [Workshopへアップロード]
```

### 制作パイプライン
*   **ステージ1：資料収集とジオメトリ作成：** 正確なスケール感が極めて重要です。クリエイターは通常、Blenderなどのモデリングソフトでロー〜ミドルポリゴンのメッシュを作成し、広角カメラ時のパフォーマンスを維持するために個別のLOD（詳細度）レベルを設定します。
*   **ステージ2：マテリアルマップ：** リアルな輸送機械には、経年劣化したスチール、色褪せた塗装、安全表記デカール、反射ガラスなどが不可欠です。アルベド、ラフネス、メタリック、ノーマルマップを正確に設定することで、車両が動的ライティングにリアルに反応するようになります。
*   **ステージ3：設定とスクリプト：** すべてのアセットには`.mdl`設定ファイルが必要です。このファイルで乗客定員、エンジンの馬力、最高速度、購入コスト、サウンドセットの割り当てなどを定義します。
*   **ステージ4：テストとパッケージング：** Transport Fever 3のSteam Workshopにアップロードする前に、制作者は隔離されたサンドボックスマップでバウンディングボックス、乗客のアニメーション、煙のエミッターなどをテストします。

| 制作工程 | 主な使用ツール | 標準的なアセット要件 |
| :--- | :--- | :--- |
| **3Dモデリング＆LOD** | Blender、3ds Max | LOD0（近距離用高精細）、LOD1、LOD2、LOD3（低ポリゴンのシルエット） |
| **UVマッピング＆テクスチャ** | Substance 3D Painter、Photoshop | 2048x2048または4096x4096のPBRテクスチャ（アルベド、ノーマル、メタル/ラフネス） |
| **サウンドエンジニアリング** | Audacity、各種DAWソフト | シームレスなエンジンループ、ブレーキ鳴き、ドアチャイム、警笛サンプル |
| **メタデータスクリプト** | VS Code、Notepad++ | 登場年代、コスト、ノード接続を定義する検証済み`.lua`ファイル |
| **ゲーム内アップロード** | ゲーム内標準Workshopステージングツール | 高解像度プレビューサムネイル（16:9）、更新履歴、タグ設定 |

## ゲームモードの互換性とModプレイスタイル

Modを導入した輸送マネジメントは、プレイヤーのプレイスタイルによってまったく異なる表情を見せます。シビアな収益バランスを極めるプレイヤーもいれば、無限の資金を使って実物そっくりのジオラマを作り上げるデジタル鉄道模型ファンとして楽しむプレイヤーもいます。

Transport Fever 3のSteam Workshopで何をサブスクライブすべきかは、ご自身のプレイスタイルによって完全に決まります。

```
プレイヤータイプの分類:
├── リアル志向モデラー（景観オブジェクト、手動信号、1:1スケールの再現）
├── 物流効率化エキスパート（ハードコア経済、ダイナミックな運行表、大量輸送）
└── 歴史追体験タイクーン（1850年から未来の時代への歴史的変遷）
```

サンドボックスモードでは、多くのプレイヤーが車両の老朽化を無効化し、資金を無限にして、プラットホーム上の小物、公園のベンチ、擁壁、特製植物などの装飾アセットを大量に導入します。モッダーたちも、こうしたクリエイティブな用途向けに機能を持たない装飾アイテムを多数提供しています。

逆に、難易度の高いシナリオやプロシージャルなキャリアキャンペーンに挑むプレイヤーは、Modの導入を慎重に吟味する必要があります。進行キャンペーンでMod車両を大量に使うと、低すぎる維持費のカスタム機関車などが原因でゲームバランスが崩れてしまうことがあります。

| プレイスタイルモード | 最適なModカテゴリ | 推奨される制限事項 | 主なゲームプレイ目標 |
| :--- | :--- | :--- | :--- |
| **純粋なサンドボックスジオラマ** | 静的プロップ、コストゼロアセット、地形ブラシ、フリーカメラMod | 経済スクリプトを無効化し、描画の安定性を最優先 | 都市部や山岳鉄道のフォトリアルな再現 |
| **ハードコアタイクーン** | 複雑な産業チェーン、維持費オーバーホール、高額な運行コスト | 運行コストが不自然に低い高性能架空車両を避ける | 厳しい利益率の中での黒字ネットワーク運営 |
| **歴史追体験** | 時代制限車両パック、歴史的バラスト、蒸気機関庫 | 該当する時代に到達するまで近代的な電気設備を制限 | 1850年から現代への本格的な時代の移り変わりの再現 |
| **都市高速交通（ラピッドトランジット）** | 地下鉄、高架橋、自動改札アセット | 乗客定員が実際の都市輸送量と見合っているか確認 | 都心部の道路渋滞の解消 |

Transport Fever 3のSteam Workshopからゲームの基本ルールを変更するModを導入する際は、セーブデータのプロファイルを分けて管理することを推奨します。そうしておけば、スクリプトのアップデートで不具合が発生しても、長年育ててきたキャリアセーブデータを破損から守ることができます。

## よくある質問（FAQ）

### Transport Fever 3のSteam WorkshopからModを使用しても実績（アチーブメント）は解除できますか？
本シリーズの多くの作品では、公平なリーダーボードを維持するため、コミュニティModを有効にするとデフォルトで実績の進行が無効化されます。ただし、利便性向上Modと実績解除の両方を楽しみたいプレイヤー向けに、実績獲得を安全に再有効化する小さなユーティリティスクリプトがコミュニティから公開されるのが通例となっています。

### Workshopアイテムが削除されて破損したセーブデータはどうやって復旧しますか？
制作者がTransport Fever 3のSteam Workshopからアセットを削除した場合、そのモデルを参照している既存のセーブデータは起動時にエラーを起こすことがあります。これを解決するには、クラッシュログを確認して見つからないアセットIDを特定し、コミュニティ製の代替ダミーModを導入するか、オフラインのMod管理ツールを使って不足しているモデルの参照先をバニラアセットに変更してください。

### 過去のシリーズ作品向けに作られたModは、Transport Fever 3でもそのまま動作しますか？
いいえ、変更を加えることなく自動的に動作することは稀です。3Dメッシュや生のテクスチャデータはコミュニティの変換スクリプトで移行できることが多いですが、レンダリングエンジンの変更、マテリアルシェーダーの仕様変更、車両設定ロジックの刷新などがあるため、通常はモッダー側でのファイル更新が必要になります。

### 複雑なインフラModの安全なサブスクライブ解除方法は？
Transport Fever 3のSteam Workshopからダウンロードした線路、信号、モジュール式駅アセットなどを削除する前に、まずゲームをロードして、マップ上に配置されている該当アイテムのすべてのインスタンスをブルドーザーで完全に撤去してください。マップ上から完全に消滅したことを確認してからセーブし、ゲームを終了した上でWorkshopのサブスクライブを安全に解除してください。
