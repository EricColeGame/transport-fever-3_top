## なぜダイヤ運行管理がネットワーク効率を劇的に変えるのか

従来の輸送シミュレーションでは、車両は主に自動ヘッドウェイ（等間隔運行）モデルで稼働していました。列車やバスは最低積載条件を満たすか、進行信号が出た瞬間に発車していました。この仕様は分かりやすい反面、速い車両が先行する遅い車両に追いついてしまう「団子運転（バンチング）」を頻発させ、満員の車両のすぐ後ろを空の車両が追従するという非効率を生んでいました。

Transport Fever 3でダイヤを設定することにより、プレイヤーは受動的な発車待ちから能動的なネットワーク統括へと移行できます。コミュニティの検証やプレイヤーの実績によれば、手動の発車スロット管理によって路線運営コストを最大25%削減できることが実証されています。赤信号での無駄なアイドリング燃料消費がなくなり、需要の低い時間帯に空荷で巡回し続けることも防止できるためです。

規律ある運行スケジュールを適用することで、輸送コリドーは予測可能なスループットを達成し、極めてスムーズな旅客乗り換え接続を実現できます。

| 運行管理システム | 従来のヘッドウェイシステム | ダイヤ運行管理システム |
| :--- | :--- | :--- |
| **発車管理** | 路線内の車両数に応じた動的管理 | 駅ごとの固定分・秒単位スロット |
| **ジャンクション動作** | 到着順の待機列 | 計画されたプラットホームおよび進路占有ウィンドウ |
| **乗り換え信頼性** | ばらつきが大きく、接続失敗が頻発 | パターンダイヤ（タクト運行）による高同期 |
| **車両の運用効率** | 団子運転や不均一な摩耗を招きやすい | 全車両が均等間隔を維持 |
| **ネットワークの複雑さ** | 設定は容易だがメンテナンス負荷大 | 適度な初期設定で、時間の経過によるズレなし |

## ダイヤ運行メカニクスのコア要素

運行管理エンジンを効果的に活用するには、車両の発車を制御する基本パラメータを理解する必要があります。スケジューラーは単に車両が車庫を出るタイミングを決めるだけではなく、路線上の各停車駅における目標到着時刻、停車時間枠（ドウェルウィンドウ）、プラットホーム解放タイミングを総合的に制御します。

Transport Fever 3のダイヤ設定では、発車スロットと軌道信号がどのように連動するかを把握することが不可欠です。列車が予定より早く駅に到着した場合、割り当てられた発車枠が訪れるまでホーム上で静かに待機し、後続や対向の急行列車のために前方の閉塞区間を開放し続けます。

### 発車スロットとオフピーク時の運行調整

シミュレーションサイクル中、路線の需要は常に一定ではありません。朝夕のラッシュアワーには通勤者が急増し、日中の移動需要は安定します。

高度な発車スロット設定を活用すれば、ピーク時間帯には高頻度の運行（例：3分間隔）を組み、オフピーク時間帯には運行間隔を広げる（例：6〜9分間隔）ことが可能です。この柔軟性により、リアルタイムの乗客数に合わせて運行コストを最適化できます。

### 停車時間（ドウェルタイム）と積載ポリシー

停車時間（ドウェルタイム）は、車両がプラットホームに停泊する最小時間および最大時間を指定します。最低積載ルールとダイヤスロットを組み合わせることで、原材料や乗客が不足した際に路線全体が無期限に停止してしまうのを防ぐことができます。

| ダイヤパラメータ | 機能 | 推奨設定 | 主なリスク |
| :--- | :--- | :--- | :--- |
| **目標発車時刻** | 発車する正確な時刻間隔を設定 | 毎時の特定分（例：:00、:15、:30） | スケジュールがきつすぎると後続に遅延が連鎖 |
| **最短停車時間** | 最小の停車時間を強制 | 普通列車：20〜30秒、急行：45秒 | 長すぎるとホームが混雑 |
| **最長停車時間** | 貨物・乗客の遅れに対する待機上限 | ダイヤ間隔マイナス15秒 | 供給が滞ると車両が半分空のまま発車 |
| **速度マージン（バッファ）** | 所要時間に余裕（スラック）を追加 | 最短理論値より10%〜15%余裕を持たせる | 理論上の最高運行速度がわずかに低下 |

## ステップ別ガイド：旅客乗り換えの同期テクニック

公共交通網マネージャーにとって至高の達成と言えるのが、ヨーロッパの交通計画で「*Taktfahrplan*（パターンダイヤ／クロックフェイス・スケジューリング）」と呼ばれる、高度に連携された乗り換えハブの構築です。Transport Fever 3のダイヤ設定にパターンダイヤを導入すれば、複数の支線・フィーダー線が同時に乗客を降ろして相互に乗換客を交換し、市民をホームで長時間待たせることなく一斉に出発させることができます。

高効率な旅客乗り換えハブを構築する手順：

1. **拠点ハブ（アンカー）の選定:** 都市間急行線と各支線・フィーダー路線（トラム、通勤列車、バス路線）が結節する複数のプラットホームを持つ中央ターミナル駅を決定します。
2. **往復サイクル時間の算出:** 各支線にテスト車両を走らせ、標準的な加減速曲線を考慮した基本の往復所要時間を算出します。
3. **バッファ（余裕時間）の確保:** 悪天候、信号待ち、軽微な乗降遅延に対応できるよう、所要時間に約10%のマージンを加えます。
4. **到着タイミングの対称化:** フィーダー路線が都市間急行列車の到着する2〜3分前に到着するように設定します。
5. **発車タイミングの同期:** 急行列車が到着してから2〜3分後に各方面への発車を設定し、乗客がホーム間を徒歩で移動するのに十分な時間を確保します。

```
[フィーダーバス路線が到着]  -->  00:10
[急行列車が到着]            -->  00:12
         --- 乗客乗り換えウィンドウ ---
[急行列車が発車]            -->  00:15
[フィーダーバス路線が発車]  -->  00:17
```

| 路線種別 | ネットワーク上の役割 | 標準的なサイクル枠 | 目標乗り換えウィンドウ |
| :--- | :--- | :--- | :--- |
| **都市間高速鉄道** | 主要大都市間を結ぶ長距離幹線軸 | 30分または60分 | 中央ハブへの定刻到着（:00 / :30） |
| **地域通勤列車** | 周辺都市と主要ハブを連絡 | 15分または30分 | 都市間幹線の3分前に到着 |
| **市内トラム／地下鉄** | 各市街地と中央駅間を循環連絡 | 5分または10分 | 連続的・等間隔でのパルス運行 |
| **郊外フィーダーバス** | 遠隔の村落と鉄道支線を接続 | 15分または30分 | 地域通勤列車の到着時刻に合わせて接続 |

## ダイヤ運行による貨物物流のボトルネック解消

貨物輸送ラインには、旅客とは異なる独自の物流上の課題があります。移動時間が長すぎると消滅（デスポーン）してしまう乗客とは異なり、産業用貨物はプラットホーム上に無限に積み上がっていくため、駅の許容量オーバーや工場の生産停止を引き起こす恐れがあります。産業用ループに特化したTransport Fever 3のダイヤグラムを組むことで、重量貨物列車が都市間の旅客輸送用本線を圧迫する事態を回避できます。

貨物列車が高速旅客列車と同じ線路を共用する場合、運行枠（ディスパッチウィンドウ）の管理が極めて重要になります。重量貨物向けに夜間やオフピーク時の専用スロットを割り当てることで、混雑時間帯における高速旅客輸送用の線路容量を確保できます。最新のパッチノートやシステム仕様の詳細については、[公式Urban Games開発者ポータル](https://www.urbangames.com/)で直接確認できます。

| 貨物路線タイプ | 典型的なボトルネック | ダイヤによる解決策 | 出力効率の向上 |
| :--- | :--- | :--- | :--- |
| **原材料シャトル** | 満載になるまで列車が無期限待機 | 積載率に関わらず固定発車枠を強制 | 車両回転率が18%向上 |
| **共用コリドー貨物** | 重量列車が高速旅客列車を減速させる | オフピーク時間帯に進路占有スロットを割り当て | 旅客輸送の遅延が35%減少 |
| **複合資源配送** | 復路の空荷走行が多額の維持費を発生 | 到着スロットを同期させた双方向ループの構築 | 空荷運行コストを50%削減 |
| **港湾・港口トランスファー** | 船の一斉到着で駅の保管許容量がパンク | 船の着岸間隔に合わせて鉄道シャトルを同期 | 駅での貨物減耗がほぼゼロに |

プレイヤーの実績からも、原材料シャトルを厳格な4分周期で発車させることで、サプライチェーンへの悪影響を防げることが分かっています。製鉄所が石炭と鉄鉱石を4分ごとに同時受け入れできれば、保管ヤードを溢れさせることなく、常に最高効率で生産を維持することが可能です。

## 高度な信号システム、優先経路、競合回避

どれほど完璧なダイヤを設計しても、物理的な線路レイアウトに適切な信号階層が備わっていなければ機能しません。Transport Fever 3のダイヤ設定と閉塞信号の配置を最適化することで、複雑なジャンクションのボトルネック（スロート）で生じる「原因不明の遅延」を根絶できます。

ダイヤ運行は、線路区間が均等な閉塞長に分割されているときに最も効果を発揮します。ある閉塞区間の通過に90秒かかり、隣接する閉塞区間が20秒しかかからない場合、長い方の区間がスケジュール可能な最小運行間隔の基準となってしまいます。

| 信号戦略 | 設置原理 | ダイヤ運行路線への影響 | 最適な用途 |
| :--- | :--- | :--- | :--- |
| **均等な閉塞間隔** | 平均制動距離に合わせて信号機を等間隔配置 | 閉塞クリアにかかる時間を安定化 | 高速専用コリドー |
| **待避線（追越線）** | 時間制御された停車を伴う並行バイパスループ | 急行列車が低速の貨物列車を追い越し可能 | 混在運行を行う共用幹線 |
| **立体交差ジャンクション** | 線路平面交差の立体化 | 平面交差による対向進路の遮断を防止 | 主要駅手前の分岐部および本線分岐 |
| **ホーム抑止信号機** | プラットホーム進出直前に信号機を設置 | 指定のダイヤ発車時刻が来るまで列車を停止ロック | 複数路線が乗り入れるターミナル駅 |

スループットを最大化するには、ホーム抑止信号機をプラットホームの先端ギリギリに配置します。これにより、Transport Fever 3のダイヤ時計が指定の発車秒に達した瞬間、列車は直ちに進路を確保して遅延なく加速を開始できます。

## Transport Fever 3の時刻表（ダイヤ）に関するよくある質問

### Transport Fever 3のダイヤ機能を使って列車の団子運転を防ぐにはどうすればよいですか？
団子運転を解消するには、路線管理パネルを開き、発車モードを動的ヘッドウェイから固定ダイヤ（スケジューリング）に切り替え、主要ターミナル駅で特定の発車スロットを割り当てます。また、軽微な遅延が後続のスロットに連鎖しないよう、駅間の所要時間に10%程度の移動バッファを必ず設けてください。

### 貨物列車と旅客列車で同じダイヤスロットを共有できますか？
おすすめできません。貨物列車と旅客列車は加速性能や最高速度が大きく異なります。旅客列車には高頻度かつ高速な運行間隔（例：5〜10分間隔）を割り当て、低速の貨物列車はオフピーク専用の時間枠に組み込むか、並行する待避線を利用したダイヤを設定するべきです。

### 列車が予定の発車時刻より遅れてしまった場合はどう対処すべきですか？
車両に予期せぬ遅延が発生した場合は、速度マージンバッファを確認してください。スケジュールに十分な余裕がない場合は、駅間の許容運行時間を増やします。深刻な遅延が生じている場合は、路線管理画面の「スロットのリセット（reset slot）」操作を使用することで、後続車両を混乱させることなく、遅延した列車を次の利用可能な運行サイクルに移動させることができます。

### 厳格なダイヤを設定すると路線の収益性は低下しますか？
初期段階では、ダイヤの微調整やテスト走行、車両数の見直しが必要です。しかし一度安定すれば、ダイヤ管理されたネットワークは無管理の路線よりもはるかに高い利益率を叩き出します。運行コストが発生したままアイドリング待機する時間が減少し、旅客の乗り換え数が飛躍的に増加するほか、工場も安定した生産サイクルを維持できるようになるためです。
